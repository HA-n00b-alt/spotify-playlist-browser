# Secrets and environment

Where every environment variable lives, who owns its value, and how the copies are kept in step
(#31, [ADR 0004](adr/0004-local-master-env-files.md)). Names only: no value appears in this file, in
`.env.example`, or in the output of any script below.

## The model

- **Master copy:** the gitignored files in the **main checkout** — `.env.local` and
  `vercel-bpm-invoker-delman-site.json`. Worktrees have no copy and need none.
- **Scripts read the master from anywhere.** `scripts/lib/env.js` resolves the main checkout from
  any worktree (`MASTER_ROOT`); `pnpm dev` runs through `scripts/with-master-env.js`, which hands the
  values to Next.js as process environment.
- **Remotes are written from the master by script.** `npm run env:sync` pushes the names whose
  `source` is `local` to the targets below; nothing else is pushed.
- **The map is code.** `scripts/lib/envCatalog.js` lists every name. The table below and
  `.env.example` are generated from it (`npm run generate:env-docs`), and `check:env-contract`
  (part of verify) fails when code reads a name the catalog does not list, or when either file is
  stale.

## Commands

All run from the main checkout or any worktree, and print names and statuses only.

| Command | What it does |
|---|---|
| `npm run env:inventory` | Every name, and where it is today: master `.env.local`, each Vercel environment, GitHub Actions, the `bpm-service` Cloud Run service. `-- --markdown` prints a table. |
| `npm run env:drift` | Compares the master and each remote against the catalog; exits 1 on drift. Not part of verify: it needs the Vercel, `gh` and `gcloud` logins. |
| `npm run env:sync` | Dry run of the sync: what would be added, changed or removed. `-- --write` applies it; `-- --prune` also removes names a target should not hold. `-- --only=vercel` (or `github`, `cloudrun`) limits the remotes. |
| `npm run generate:env-docs` | Rewrites `.env.example` and the table below from the catalog. |

`deploy:production` runs `env:sync --only=vercel --write` as one of its steps.

### Drift statuses

| Status | Meaning | Fix |
|---|---|---|
| `added` | A synced name the target lacks | `env:sync -- --write` |
| `changed` | A synced name whose value differs from the master | `env:sync -- --write` |
| `unknown` | A synced name the target holds write-only (Vercel `sensitive`) | none needed; `--write` rewrites it |
| `removed` | A name the catalog owns that the target should not hold | `env:sync -- --write --prune` |
| `missing` | A name set by hand in Vercel or by an integration that the target lacks | set it in Vercel |
| `extra` | A name the target holds that this repository does not own there | none; reported only |
| `missing-required` | A required name empty in the master `.env.local` | fill it in the main checkout |
| `not-needed` | A name in the master `.env.local` the code does not read (a `vercel env pull` leftover) | optional cleanup |
| `unlisted` | A name nobody catalogued | add it to `scripts/lib/envCatalog.js` |

## Owners (`source`)

| Source | Owner of the value | Pushed by `env:sync` |
|---|---|---|
| `local` | the master `.env.local` | yes |
| `vercel` | set by hand per Vercel environment, because the value differs per environment; the local value is the development one | no |
| `integration` | a Vercel Marketplace integration (Neon, Blob); the local copy was pulled from Vercel | no |
| `default` | nobody: the code has a default | no |
| `platform` | Node, Next.js or Vercel at run time | no |
| `operator` | a flag passed to a script | no |

## Target placement

Vercel **preview** is not a target: preview deployments are off (the project is not connected to
git). **GitHub Actions** has no workflows, so nothing belongs there. **Cloud Run** services belong
to the BPM service repository; this repository only needs the invoker key, which lives in Vercel.

## Current state and drift (2026-10-03)

Taken with `npm run env:inventory` and `npm run env:drift` when this map was written. Rerun them for
the live picture.

**Local (main checkout).** Every required name is set. Fifteen names are `vercel env pull`
leftovers the code never reads (`NEON_PROJECT_ID`, the `PG*` and `POSTGRES_*` integration copies,
`VERCEL_OIDC_TOKEN`); they are harmless and can be deleted from the master `.env.local`.

**Vercel.**

- `NEXT_PUBLIC_UMAMI_WEBSITE_ID` is in no Vercel environment. Production analytics work only because
  the deploy builds on the laptop, where Next.js reads the local `.env.local`. The next
  `deploy:production` (or `env:sync -- --only=vercel --write`) adds it to production and
  development.
- `SPOTIFY_CLIENT_ID`, `SPOTIFY_CLIENT_SECRET`, `NEXT_PUBLIC_SENTRY_DSN` and the three `SENTRY_*`
  names are also in preview, which is unused: `removed` until pruned with
  `env:sync -- --only=vercel --write --prune`. `SPOTIFY_REDIRECT_URI` and `NEXT_PUBLIC_BASE_URL` in
  preview are reported as `extra` and left alone.
- `BPM_SERVICE_URL` and `GCP_SERVICE_ACCOUNT_KEY` are `sensitive` in production, so their values
  cannot be compared; they are rewritten on every deploy, as before. Every other synced name
  matches the master.

**GitHub.** No Actions secrets or variables, and no workflows.

**Cloud Run** (`delman-site`, `europe-west3`). `bpm-service` holds `GOOGLE_CLOUD_PROJECT` and
`LOG_LEVEL` as plain values, owned by the BPM service repository. `vercel-bpm-invoker` holds
`roles/run.invoker` on it. Secret Manager is disabled in the project, so no secret is stored there.
